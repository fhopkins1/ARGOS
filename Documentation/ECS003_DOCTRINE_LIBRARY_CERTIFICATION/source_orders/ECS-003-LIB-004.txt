# ECS-003-LIB-004

# Generic Office Instantiation Engine

## Doctrine Statement

### Purpose

This work order establishes the authoritative Generic Office Instantiation Engine governing deterministic generation of office-specific ECS-003 remediation doctrine from the certified generic ECS-003 remediation library.

The Engine shall transform one authoritative office-definition package into a complete, internally consistent, office-specific remediation program without manually rewriting generic doctrine.

The Engine shall instantiate:

* office identity;
* constitutional terminology;
* canonical object terminology;
* dependency terminology;
* interface terminology;
* behavioral obligation terminology;
* evidence terminology;
* proof terminology;
* certification terminology;
* office-specific remediation identifiers;
* office-specific cross-references;
* office-specific deliverable requirements.

The Engine shall use the generic remediation programs established under:

* **ECS-003-RM-B01** — Dependency-Derived Implementation Discovery;
* **ECS-003-RM-B02** — Behavioral Verification;
* **ECS-003-RM-B03** — Implementation Remediation;
* **ECS-003-RM-B04** — Initial Proof Generation and Certification;
* **ECS-003-RM-B05** — Independent Reproduction Audit;
* **ECS-003-RM-B06** — Behavioral Coverage and Dependency-Derived Discovery Remediation;
* **ECS-003-RM-B07** — Evidence, Proof, and Traceability Remediation;
* **ECS-003-RM-B08** — Clean-Room Reproducibility Remediation;
* **ECS-003-RM-B09** — Fail-Closed Certification Validation.

The generic ECS-003 remediation library shall remain immutable during instantiation.

Instantiation shall specialize doctrine without altering its constitutional meaning, certification obligations, fail-closed behavior, evidence requirements, proof requirements, reproducibility requirements, or completion criteria.

Every generated office-specific program shall remain independently auditable.

Every generated artifact shall preserve deterministic lineage to:

* the generic source doctrine;
* the office-definition package;
* the instantiation-engine version;
* the template version;
* the generation execution;
* the resulting office-specific artifact.

No office-specific doctrine shall be generated through unrestricted prose synthesis.

No required doctrine shall be silently omitted.

No office-specific constitutional fact shall be invented.

No unresolved office-specific input shall be silently resolved.

---

# Constitutional Principles

The generic ECS-003 remediation library shall constitute the authoritative source doctrine.

Office-specific generation shall constitute deterministic specialization, not doctrinal authorship.

Generic doctrine shall never be mutated during instantiation.

Every substituted value shall originate from one authoritative office-definition field.

Every generated statement shall trace to either:

* immutable generic doctrine; or
* authoritative office-specific input.

Every office-specific input shall possess one canonical identity.

Every generated office-specific program shall preserve the sequence, scope, purpose, and completion obligations of the generic B01–B09 lifecycle.

No generated program shall weaken:

* dependency-derived discovery;
* executable behavioral verification;
* evidence integrity;
* proof sufficiency;
* traceability;
* independent reproduction;
* clean-room isolation;
* fail-closed certification.

Missing mandatory input shall cause generation to fail closed.

Ambiguous mandatory input shall cause generation to fail closed.

Contradictory mandatory input shall cause generation to fail closed.

Unknown placeholders shall cause generation to fail closed.

Unresolved cross-references shall cause generation to fail closed.

Unresolved identifiers shall cause generation to fail closed.

Every generation execution shall be deterministic and independently reproducible.

Equivalent normalized inputs shall produce semantically equivalent outputs.

Historical generated artifacts shall never be overwritten.

Superseded generated artifacts shall remain preserved.

---

# Objective

Implement one deterministic engine capable of accepting an authoritative office-definition package and generating a complete office-specific ECS-003 remediation doctrine package covering B01 through B09.

The Engine shall eliminate repetitive manual doctrine rewriting while preserving office-specific accuracy, constitutional authority, internal consistency, historical lineage, and certification integrity.

# Fail-Closed Rules

The Engine shall refuse generation or release when:

* the input schema is invalid;
* a mandatory input is missing;
* a canonical identity is duplicated;
* an office authority is contradictory;
* ownership is contradictory;
* a lifecycle is contradictory;
* a dependency is unresolved;
* an interface is unresolved;
* a required behavioral obligation is missing;
* a required evidence obligation is missing;
* a required proof obligation is missing;
* a placeholder remains unresolved;
* a cross-reference remains unresolved;
* a generated clause semantically diverges from generic doctrine;
* a required program is absent;
* a required subordinate order is absent;
* an unauthorized extension is present;
* deterministic regeneration fails;
* lineage is incomplete.

The Engine shall never issue a successful generation status merely because files were produced.
