# PERFORMANCE-TRUTH-ECS003-AUDIT-004

# Independent Clean-Room Runtime Reproduction and Final ECS-003 Certification Audit

## Purpose

Perform the independent runtime reproduction required to determine whether the Performance Truth Office satisfies ECS-003.

This audit shall execute the submitted **PERFORMANCE_TRUTH_ECS003_AUDIT003A Repository Package ZIP** from a newly created clean-room workspace using the repository-provided independent reproduction entrypoint.

The audit shall generate its own evidence through direct execution.

Repository-supplied evidence, historical reports, previous certification decisions, and prior audit conclusions shall not constitute proof.

This audit shall issue exactly one final ECS-003 decision:

* **PASS**
* **FAIL**

Conditional certification is prohibited.

## Candidate Inputs

Use the submitted Audit-003A packages:

* Repository Package ZIP;

The Repository Package ZIP is the sole executable candidate.

The Evidence Package ZIP shall remain isolated until independent execution and evidence generation are complete.

Record the cryptographic hash and file size of both packages before beginning.

---

## Non-Modification Rule

The auditor shall not modify the submitted candidate.

The auditor shall not:

* repair source code;
* repair configuration;
* add missing dependencies not authorized by repository instructions;
* change tests;
* change expected outputs;
* suppress failures;
* retry selectively to conceal instability;
* exclude discovered tests without constitutional authority;
* reinterpret failed behavior;
* infer intended behavior;
* substitute generated artifacts;
* make architectural or business-logic decisions.

If the candidate cannot reproduce successfully as delivered, record the failure and continue only where further execution remains possible without repair.

---

## Auditor Independence

Treat all repository-supplied claims as unverified.

Do not accept as proof:

* certification reports;
* completion reports;
* packaged execution logs;
* historical test results;
* self-validation results;
* generated manifests;
* assertions that previous audits passed.

Only evidence generated during this audit may support the certification decision.

# Phase 3 — Entrypoint Verification

Locate and inspect only as necessary to invoke the canonical reproduction entrypoint documented by Audit-003A.

The expected command form is:

```text
python audit_reproduce.py --candidate <repository-package.zip> --output <empty-output-directory>
```

Use the exact documented command unless the package itself specifies another canonical Performance Truth command.

Do not alter the entrypoint.

Before execution, confirm that:

* it identifies Performance Truth rather than another office;
* it accepts the Repository Package ZIP;
* it requires an empty output destination;
* it does not require the Evidence Package;
* it does not load historical certification artifacts as proof;
* it records commands, exit codes, outputs, and failures;
* it does not issue the final ECS-003 certification decision.

Any violation shall be recorded as an audit finding.

# Phase 10 — Fail-Closed Verification

Verify runtime exercise of at least the following conditions:

* missing evidence;
* corrupted evidence;
* contradictory evidence;
* invalid ownership;
* duplicate input;
* temporal disorder;
* reconciliation failure;
* dependency failure;
* invalid configuration;
* invalid calculation input.

For each scenario determine:

* how the fault was introduced;
* which constitutional control detected it;
* whether unsafe continuation occurred;
* whether prohibited truth was published;
* whether the failure was recorded;
* whether recovery behavior remained deterministic.

Unsafe continuation or unsupported fail-closed claims shall constitute failure.

---

# Phase 11 — Mutation Verification

Inspect each mutation result generated during the independent runs.

For every mutation record:

* mutation identifier;
* mutated target;
* exact altered condition;
* expected constitutional consequence;
* actual detection mechanism;
* test or runtime control that detected it;
* observed output;
* result.

Reject any mutation as invalid where detection occurred only because:

* the harness recognized its own marker;
* the mutated fixture declared itself invalid;
* a special mutation-only branch returned failure;
* the ordinary constitutional control was not exercised.

Undetected constitutional mutations shall constitute certification failure.

# Certification Rules

Issue **PASS** only if all of the following are true:

* both independent clean-room runs complete;
* both runs return successful documented exit status;
* all required Performance Truth tests execute;
* no required test fails, errors, times out, or remains unjustifiably skipped;
* required behaviors are proven by runtime evidence;
* deterministic outputs reproduce equivalently;
* replay succeeds;
* fail-closed scenarios prevent unsafe continuation;
* mutations are detected through ordinary constitutional controls;
* stress execution preserves constitutional guarantees;
* cross-office boundaries are adequately exercised;
* the reproduction harness does not manufacture results;
* submitted evidence is not materially contradicted;
* no unresolved certification-blocking finding remains.

Issue **FAIL** if any PASS condition is not satisfied.

Absence of evidence shall be treated as failure of the applicable requirement.

---

# Final Decision

Issue exactly one:

## PASS

State:

> The Performance Truth Office has been independently reproduced from the submitted Repository Package ZIP through two clean-room runtime executions. The independently generated evidence establishes that every applicable ECS-003 constitutional, implementation, behavioral, determinism, replay, evidence, traceability, reconciliation, mutation-resistance, stress, interface, and fail-closed requirement has been satisfied.

or:

## FAIL

State:

> The Performance Truth Office has not satisfied independent ECS-003 runtime certification.

List every certification-blocking finding and its objective evidence.

Do not issue:

* conditional PASS;
* provisional PASS;
* substantial compliance;
* apparent compliance;
* structurally complete;
* ready for certification;
* PASS subject to later execution.
