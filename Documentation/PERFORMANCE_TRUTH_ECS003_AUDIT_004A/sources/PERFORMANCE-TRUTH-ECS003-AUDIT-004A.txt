# Required Corrections

## 1. Remove the Developer-Local Dependency

Eliminate all active runtime dependence on:

```text
C:\Users\Fletc\.codex\attachments\8b57da45-406a-4e10-a43a-fa76ff327f2d\pasted-text.txt
```

Search the complete repository for:

* the exact path;
* the attachment identifier;
* `pasted-text.txt`;
* equivalent absolute local paths;
* environment-specific developer paths.

Every active reference shall be removed from the execution path.

Required source material shall be:

* included within the repository package;
* identified by a repository-relative path;
* cryptographically bound to the candidate package;
* documented in the auditor guide.

Codex shall not reconstruct missing source material from memory or inferred intent.

If the required source material is absent, classify the order as `INCOMPLETE`.

---

## 2. Establish Repository-Relative Input Resolution

All required audit inputs shall resolve from the extracted candidate root.

Input resolution shall:

* reject absolute developer paths;
* reject paths outside the extracted candidate;
* reject undocumented network retrieval;
* reject hidden user-profile dependencies;
* record the resolved path and file hash;
* fail closed when a required input is absent.

Add tests proving rejection of:

* Windows user-profile paths;
* Unix home-directory paths;
* parent-directory traversal;
* unavailable external files;
* unrecorded environment-dependent paths.

---

## 3. Correct Runtime Test Discovery

Replace predefined single-module discovery with deterministic repository-based discovery of all applicable Performance Truth runtime tests.

Discovery shall:

* begin from the extracted candidate;
* identify all Performance Truth runtime test modules;
* record every discovered test identifier;
* record all exclusions;
* require explicit constitutional justification for each exclusion;
* fail if no tests are discovered;
* fail if collection terminates with errors;
* fail if the discovered test inventory is inconsistent between identical runs.

Do not classify documentation checks, file-presence checks, or report-generation checks as runtime behavioral tests.

---

## 4. Enforce Zero-Test Failure

The audit harness shall fail whenever:

* zero tests are collected;
* zero tests are executed;
* collection fails before test execution;
* all tests are skipped;
* the controlling test process terminates before completing required tests.

The harness shall preserve the raw framework result, including:

* collected count;
* executed count;
* passed count;
* failed count;
* error count;
* skipped count;
* deselected count;
* timeout count;
* interruption count;
* process exit code.

A summarized count shall not conceal `Ran 0 tests`.

---

## 5. Establish Controlling Execution Gates

Each certification-relevant artifact shall identify its controlling execution.

At minimum, independently gate:

* behavioral results;
* replay results;
* fail-closed results;
* mutation results;
* stress results;
* cross-office results;
* final execution summary.

A result may be marked `PASS` only when:

* its controlling command executed;
* the controlling command completed;
* the controlling command returned the required successful exit code;
* required raw outputs exist;
* required assertions executed;
* no upstream blocking dependency failed.

If a controlling execution fails, the dependent artifact shall be marked:

* `FAIL`; or
* `NOT_EXECUTED`.

It shall never be marked `PASS`.

---

## 6. Propagate Failures Deterministically

The reproduction entrypoint shall calculate its final exit status from raw controlling executions.

It shall return nonzero if any required phase is:

* failed;
* errored;
* timed out;
* interrupted;
* incomplete;
* not executed;
* missing evidence;
* unsupported.

No later artifact-generation phase may overwrite or neutralize an earlier failure.

Add tests proving that failure in each required phase forces a nonzero final exit.

---

## 7. Prevent Template or Synthetic PASS Generation

Review every evidence generator for:

* hard-coded PASS values;
* default-success values;
* PASS templates;
* file-presence-only success;
* exception suppression;
* failure-to-empty conversion;
* missing-result-to-PASS conversion.

Remove all such behavior from the active audit path.

Every certification-relevant status shall be derived from recorded raw execution.

The output shall include the derivation chain from:

```text
raw command
→ raw result
→ phase result
→ final reproduction result
```

---

## 8. Bind Every Output to the Exact Candidate

Every generated artifact shall include:

* Repository Package SHA-256;
* extracted candidate root hash or manifest hash;
* audit run identifier;
* generation timestamp;
* controlling command identifier;
* tool or script version;
* result status.

The reproduction harness shall reject any externally supplied artifact whose candidate hash does not equal the current Repository Package hash.

Historical evidence may be compared only after execution and shall remain classified as external evidence.

---

## 9. Correct Evidence-Package Generation

The Evidence-Only Package shall contain only artifacts generated from the current candidate execution.

It shall not include as current evidence:

* previous Audit-003 evidence;
* previous Audit-003A evidence;
* previous Audit-004 evidence;
* self-validation evidence from a different candidate;
* reports whose embedded candidate hash differs;
* copied historical PASS conclusions.

Before packaging, perform a candidate-hash consistency check across every evidence artifact.

Any mismatch shall block packaging.

---

## 10. Establish Repository and Evidence Package Pairing

Generate the Repository Package and Evidence-Only Package from one controlled packaging operation.

Both package names shall contain the same package-set identifier.

Produce a package-set manifest containing:

* Repository Package filename;
* Repository Package SHA-256;
* Evidence Package filename;
* Evidence Package SHA-256;
* candidate source commit or repository state identifier where available;
* audit run identifier;
* packaging timestamp;
* evidence candidate hash;
* package-set consistency result.

The evidence candidate hash must equal the Repository Package hash actually audited.
