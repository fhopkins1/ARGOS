# CLOSED-POSITION-TRUTH-RM-002-B07-002-002

# Independent Verifier and Fixture Discovery

## Objective

Independently discover every verifier, test harness, executable verification entry point, and fixture participating in the Closed Position Truth Office behavioral certification campaign.

Discovery shall originate exclusively from the extracted Repository Package ZIP and the deterministic clean-room environment validated under **CLOSED-POSITION-TRUTH-RM-002-B07-001**.

No verifier inventory, fixture inventory, expected execution count, prior certification artifact, historical execution log, or manually maintained registry shall be accepted as authoritative discovery input.

No implementation shall be modified.

No behavioral verification shall occur under this order except where minimally necessary to establish discovery identity, collection behavior, or participation.

No mutation campaign shall occur.

No proof generation shall occur.

No certification verdict shall be issued.

---

# Discovery Authority

Verifier and fixture participation shall be established through objective repository and runtime evidence.

Participation may be demonstrated through:

* test collection;
* test-runner discovery;
* executable registration;
* module imports;
* runtime invocation paths;
* dependency graphs;
* fixture injection;
* parameterization;
* setup and teardown participation;
* persistence construction;
* replay construction;
* recovery construction;
* environment construction;
* evidence-generation participation;
* shared harness invocation.

Participation shall not be established solely through:

* filenames;
* directory names;
* documentation;
* comments;
* naming conventions;
* previous manifests;
* prior execution totals;
* previous PASS or FAIL reports;
* developer assertions.

Execute the repository-native collection or discovery mechanism without performing the full behavioral campaign.

Verify:

* deterministic verifier collection;
* deterministic fixture discovery;
* stable collection identity;
* stable verifier count;
* stable parameterized execution population;
* stable fixture binding;
* absence of dependency upon collection caches;
* absence of dependency upon prior execution artifacts;

Any variance in discovered participation shall be preserved as a finding.

# Orphan and Duplicate Detection

Identify every:

* verifier not reachable through the certification execution path;
* verifier collected but never executable;
* verifier dependent upon unavailable fixtures;
* verifier lacking an identifiable behavioral obligation;
* fixture not consumed by any discovered verifier;
* fixture shadowed by another fixture;
* duplicate verifier implementation;
* duplicate parameterized execution;
* duplicate fixture construction;
* disabled verifier;
* skipped verifier;
* quarantined verifier;
* conditionally excluded verifier;
* verifier excluded by configuration or environment.

Skipped, disabled, quarantined, or conditionally excluded verifiers shall not be treated as successfully participating.

# Deterministic Identity Requirements

Every verifier, fixture, and parameterized execution population shall receive a deterministic identity derived from stable repository and collection evidence.

Identity shall not depend upon:

* nondeterministic collection order;
* temporary paths;
* workstation usernames;
* process identifiers;
* timestamps;
* memory addresses;
* random values;
* prior execution identifiers.

Repeated discovery shall produce identical identities for an unchanged Repository Package ZIP and environment.
