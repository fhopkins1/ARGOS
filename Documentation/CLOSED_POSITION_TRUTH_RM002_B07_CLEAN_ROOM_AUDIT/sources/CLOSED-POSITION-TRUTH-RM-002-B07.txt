# CLOSED-POSITION-TRUTH-RM-002-B07

# Independent Clean-Room Reproduction and Fail-Closed Certification Audit

## Doctrine Statement

### Purpose

This order establishes the independent clean-room reproduction campaign required to verify the Closed Position Truth Office implementation certification without relying upon the prior certification execution, prior generated evidence, developer-local state, hidden repository state, or previously asserted conclusions.

This order exists solely to determine whether the complete **CLOSED-POSITION-TRUTH-RM-002** certification result can be independently reproduced from the delivered Repository Package ZIP in a newly created isolated environment.

The prior implementation certification package shall be treated only as the comparison baseline.

It shall not be treated as proof of successful reproduction.

The clean-room campaign shall independently reproduce:

* repository validation;
* environment construction;
* dependency-derived implementation discovery;
* runtime participation discovery;
* verifier discovery;
* fixture discovery;
* behavioral verification;
* evidence generation;
* requirement-level proof generation;
* implementation traceability;
* certification blocker determination;
* fail-closed mutation validation;
* final ECS-003 implementation certification assessment.

No prior generated evidence artifact may be reused as execution evidence.

No prior proof artifact may be reused as reproduced proof.

No prior certification conclusion may be imported into the reproduced verdict.

No implementation remediation shall occur under this order.

Any discovered defect shall be recorded as a finding and shall fail closed.

---

# Governing Baselines

The constitutional architecture established under **CLOSED-POSITION-TRUTH-RM-001** and its accepted follow-on constitutional completion artifacts shall be treated as the authoritative constitutional baseline.

The implementation delivered in the **CLOSED-POSITION-TRUTH-RM-002 Repository Package ZIP** shall be treated as the frozen implementation candidate.

The **CLOSED-POSITION-TRUTH-RM-002 Evidence Package ZIP** shall be used only after independent execution for objective comparison.

The clean-room auditor shall not use the submitted evidence package to determine:

* implementation participation;
* verifier participation;
* fixture participation;
* expected execution counts;
* expected proof counts;
* expected mutation results;
* certification readiness;
* final verdict.

These values shall first be independently derived.

---

# Independence Requirements

The campaign shall execute in a new isolated working directory.

The campaign shall not depend upon:

* the original source checkout;
* Git metadata;
* Git history;
* developer workstation configuration;
* pre-existing virtual environments;
* pre-existing dependency caches unless their contents are fully identified and verified;
* prior generated registries;
* prior execution logs;
* prior evidence objects;
* prior proof objects;
* prior traceability graphs;
* prior certification reports;
* undocumented environment variables;
* undocumented secrets;
* undocumented external services;
* manually curated implementation inventories;
* manually curated verifier inventories;
* manually curated fixture inventories.

The campaign shall begin from only:

1. the delivered Repository Package ZIP;
2. the frozen constitutional baseline;
3. documented runtime prerequisites;
4. the clean-room audit order.

If the repository package cannot execute without unavailable hidden state, the campaign shall issue **NOT_REPRODUCIBLE**.

# Order Structure

## CLOSED-POSITION-TRUTH-RM-002-B07-001

# Clean-Room Repository Validation

## Objective

Validate that the delivered Repository Package ZIP is complete, self-contained, extractable, and suitable for independent execution.

## Required Actions

1. Extract the repository into a new empty directory.
2. Generate a complete content manifest.
3. Record package and extracted-content hashes.
4. Identify all declared runtime prerequisites.
5. Identify all configuration inputs.
6. Identify all environment variables.
7. Identify all external service dependencies.
8. Identify all generated-artifact dependencies.
9. Confirm whether Git metadata is required.
10. Confirm whether any source, verifier, fixture, configuration, or dependency is referenced but absent.

The audit shall not reconstruct missing files from the Evidence Package ZIP.

## Fail Conditions

Fail if:

* extraction is incomplete;
* referenced files are missing;
* execution requires Git metadata not delivered;
* execution requires undocumented local state;
* required configuration is absent;
* required external dependencies cannot be deterministically isolated;
* the package depends on prior generated evidence.

## Deliverables

* Clean-Room Repository Manifest;
* Repository Identity Registry;
* Repository Completeness Report;
* Missing Dependency Registry;
* Clean-Room Readiness Assessment.

## CLOSED-POSITION-TRUTH-RM-002-B07-006

# Independent Fail-Closed Mutation Campaign

## Objective

Independently demonstrate that the certification system rejects constitutionally defective Closed Position Truth implementations.

## Mutation Independence

Do not rely solely upon the seven prior submitted mutations.

Independently derive mutation classes from the frozen constitutional requirements.

Prior mutation cases may be compared only after the independent mutation plan is complete.

Each mutation shall:

* alter exactly one governing behavior where practical;
* possess deterministic identity;
* identify the violated requirement;
* identify the expected certification blocker;
* preserve all unrelated implementation behavior where practical;
* execute through the same certification pipeline as the unmodified candidate;
* be removed before the next mutation unless explicitly testing combined defects.

## Mandatory Mutation Classes

Include at least one controlled mutation for each applicable domain:

1. create authoritative truth before execution completion;
2. create authoritative truth with positive residual quantity;
3. accept unresolved reconciliation;
4. bypass settlement verification or exemption;
5. permit degraded analytical inputs to create authoritative truth;
6. mutate an immutable closed-position record;
7. overwrite rather than supersede a prior record;
8. lose correction or supersession lineage;
9. accept duplicate closure as a new authoritative record;
10. accept stale or conflicting evidence;
11. omit required evidence while retaining a PASS verdict;
12. remove a required verifier;
13. remove a required implementation participant from discovery;
14. break requirement-to-execution traceability;
15. inject circular or self-certifying proof;
16. reuse prior evidence rather than regenerate evidence;
17. corrupt replay or restart recovery;
18. alter realized outcome ownership or derivation;
19. permit unauthorized upstream or downstream mutation;
20. omit a certification blocker while a known defect exists.

## Required Validation

For every mutation verify:

* the behavioral verifier fails where applicable;
* the evidence records the defect;
* the requirement proof becomes `NOT_PROVEN`;
* the certification blocker is created;
* the final certification verdict is not PASS;
* no unrelated false-positive blocker is introduced where practical.

Record:

* true positives;
* false positives;
* true negatives;
* false negatives.

Any false negative shall fail the campaign.

Any unexplained false positive shall fail the campaign.

## Deliverables

* Independent Mutation Plan;
* Mutation Registry;
* Mutation Execution Registry;
* Mutation Evidence Registry;
* Mutation Blocker Registry;
* False-Positive and False-Negative Report;
* Fail-Closed Validation Report.

* copy prior evidence into the reproduced evidence directory;
* copy prior proof into the reproduced proof directory;
* use prior participant inventories as discovery inputs;
* use prior execution counts as acceptance criteria;
* accept aggregate test success without raw execution evidence;

* mark unexecuted requirements as proven;
* conceal failed tests through filtering;
* modify the implementation candidate;

* issue PASS because results appear consistent with the prior package.
